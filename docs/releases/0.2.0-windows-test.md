# Legio 0.2.0 Windows acceptance test

The release PR adds Store filters, optional application logging, the native Windows artwork dispatch fix, prioritized artwork loading with persistent cache revalidation, stable dialog blur and foreground page fades, Dither lifecycle recovery, and window/calendar layout fixes. The Windows CI job produces an NSIS installer before merge. Keep the PR open until the Windows acceptance test succeeds.

## Obtain the installer

1. Open the latest CI run for the release PR.
2. Wait for `Tauri smoke (Windows)` to succeed.
3. Download the artifact named `legio-windows-pr-<PR number>-<head SHA>` and extract it.
4. Check `build-info.txt` against the PR head revision. It records both the PR head and the merge revision compiled by CI.
5. Verify the installer with `SHA256SUMS.txt`, then run the `.exe` installer.

This installer uses the production application profile. Back up an existing Legio profile before testing. Updater artifact signing is disabled for this test build; it is not a published release. The release workflow continues to sign updater artifacts after merge.

## Store checks

- Confirm the defaults are `Most relevant` and `All`.
- Search for an exact title and a partial title. Confirm the closest matches come first.
- Compare alphabetical ascending and descending ordering, including when the search is empty.
- Add a valid download source containing verified and unverified games. Confirm `Available only` includes both and excludes unavailable games. Confirm `Verified only` includes only games with at least one verified release.
- Confirm a title with several releases appears once and its releases remain selectable on the detail page.
- Check a source title that is not yet in the catalog cache. It must appear and be searchable.
- Load several pages, then change either filter. Confirm the list restarts at 20 games and the selected filters remain active when loading more.
- Switch filters quickly while searching. Confirm older requests do not replace the current results.
- Remove or refresh a source. Confirm availability filters use the updated source state.
- With no sources installed, confirm the availability filters show an empty state and both controls remain usable.
- Test cached searches offline. Confirm a failed refresh retains the local results and offers a retry.
- Check both Italian and English labels and keyboard navigation for both menus.

## Windows regression checks

- Start and restart the installed app; confirm settings and library persist.
- Open Library and Store repeatedly, with an empty library and existing games, in both windowed and maximized modes. Test with application logging off and on. The reported Windows crash remains an acceptance blocker until diagnosed and retested.
- Add, launch and stop an existing game; confirm the launcher finds its executable and records playtime.
- Exercise a small download through a valid source, including extraction and finalization.
- Check Steam detection, tray behavior, artwork and dialogs.
- Confirm the native window cannot be resized below 960x540 logical pixels. Below 1280x720, the whole interface scales proportionally to fit, reaching 75% at the minimum and returning to 100% at 1280x720 or larger. Test non-proportional resizing and Windows display scaling, including moving between monitors with different scaling.
- At the minimum, check Settings, dropdown alignment, pointer targets, fullscreen artwork and keyboard focus. Keep a dialog open while resizing and maximizing/restoring.
- Confirm Library, Store, game details and Settings do not create horizontal or vertical document scrollbars. Long page content should scroll within its intended content area. Check expanded and collapsed sidebars on Windows and Linux.
- Confirm calendar cells remain square for five-week and six-week months. Check Italian/English and both sidebar states.
- At the minimum size, scroll Home to reach recent games. Confirm calendar controls, news scrolling and Settings remain reachable with five recent games.

## Application and network logging

- On a new profile, both `Save application logs` and `Save network logs` are off. Missing preferences also default to off; explicitly saved choices are preserved.
- Enable application logging in Settings, then restart Legio. Confirm `app.txt` appears in the folder shown in Settings. Enable/disable network logging independently.
- Navigate to Home, Library, Store and a game detail. Confirm application records contain page categories, version, platform and session information without game identifiers or titles.
- Confirm `app.txt` records startup, navigation, native command failures, renderer errors, unhandled rejections and Rust panics when enabled. Shutdown records require exiting Legio completely, rather than minimizing to the tray.
- Disable application logging and confirm subsequent navigation and errors do not append application records. Existing files remain available. The logger retains at most `app.txt` and `app.previous.txt`, each bounded to 256 KiB.
- Check that private paths, URLs and credentials are redacted. Technical event names, error types and numeric source locations remain useful for diagnosis.

To diagnose the reported Library crash, enable application logging, restart Legio, open Library and send `app.txt` plus `app.previous.txt` if present. For the installed Windows profile, the log folder is `%LOCALAPPDATA%\dev.fraa2a.legio\logs`; development builds use a separate `.dev` identifier.

The supplied RestartManager event 10001 is an informational session event. It does not identify the faulting module. If the process exits with no recorded Rust panic or JavaScript error, also collect the nearby `Application Error` event 1000 or `Windows Error Reporting` event 1001, including faulting application/module and exception code. The native Windows observers record WebView2 runtime version, process failures (kind, reason and exception/exit code when supported), and browser process exits. These records bypass renderer reporting. A fatal fault in Legio itself, forced termination or a system shutdown can still stop the process before an error record is written. Native image and IPC checkpoints use a bounded asynchronous queue so logging cannot block conversion or publication. Navigation records are sent asynchronously; logging does not delay the foreground fade or page swap. Pending image records can be lost when the host terminates; panic and explicit crash diagnostics remain separate. The last persisted phase narrows the failure location but does not prove its cause.

The supplied native dump identifies stack exhaustion while dispatching `get_steam_asset` on the Windows UI thread, before the image future is polled. See [the crash analysis](0.2.0-windows-artwork-crash.md). Retest populated Library and Store with cold and warm artwork caches and animation effects enabled. A successful empty Library test alone does not cover the failing path.

If a native crash recurs, retain `Report.wer` and the `.dmp` referenced by Windows Error Reporting event 1001. If the temporary dump is gone, extract [Microsoft ProcDump](https://learn.microsoft.com/en-us/sysinternals/downloads/procdump), close Legio, open PowerShell in the extracted folder and run:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\Desktop\LegioDumps"
.\procdump64.exe -ma -e -w legio.exe "$env:USERPROFILE\Desktop\LegioDumps"
```

Leave ProcDump running, start Legio normally and reproduce the crash. ProcDump runs outside Legio and records the unhandled native exception. Keep dumps private because they contain process memory. The separate `legio-windows-symbols-pr-<PR number>-<head SHA>` CI artifact contains the matching native PDB for the test installer; symbols from another revision cannot reliably resolve its addresses.

The previous JSONL files remain untouched as evidence. New records go only to the two TXT files. Windows CI tests image conversion/blur and WebView diagnostic records in addition to the logger. The installer remains a diagnostic build until the affected Windows machine passes the acceptance test.

## Artwork cache, priority and timing acceptance

- Use the same games, visible rows, window size and network connection for each comparison. Measure cold-cache and warm-cache startup with logging off, then repeat with application logging on. Record time to the first visible cover, selected-game hero/header/logo, and all visible covers.
- Open a game while Store or Library is still loading covers. Its metadata and essential artwork must get priority. At most five network operations and two image conversions are admitted globally; ordinary work leaves capacity for the opened game. These limits include metadata, Steam artwork metadata and image transfers.
- Open games A, B and A quickly while work is queued. The final A opening must retain its own live demand, without showing B's artwork or errors.
- After three days, metadata revalidates only when the game page opens. After five days, artwork revalidates on opening. List views keep cached content and do not poll expiry. A future cache timestamp is revalidated on opening.
- Test expired caches online and offline. Previous metadata and artwork must remain visible during refresh and after failure. A new image is decoded before it replaces the old generation. A failed refresh must not advance the successful-fetch age; retries use a separate five-minute backoff. Explicit refresh remains available and does not delete the cache first.
- Enabled application logs include bounded `artwork` summaries. Native fields are `request_id`, `resource`, `queue_wait_ms`, `metadata_ms`, `transfer_ms`, `conversion_ms` and `outcome`. The frontend adds `publication_ms` covering display decode and cache publication acknowledgment. Native stage times include preempted attempts; queue wait is separate. Records do not include game names, paths or URLs. A disabled logger produces no new artwork records and log writes do not gate image display.
- Windows latency measurements are pending. Queue and cache tests establish behavior, not a measured speedup over Steam or Hydra.

## Blur, foreground fade and Dither acceptance

- With panels at 15% opacity and 6 px blur, repeat navigation with the sidebar expanded and collapsed. Inspect frames during the 105 ms exit and 105 ms entrance, not only settled pages. Sidebar logo, background and panel blur must remain stable.
- Repeat with Dither animated, Dither frozen, particles, and no effect; also test Windows reduced-motion settings. Reduced motion must bypass the timed fade.
- Drag dialog blur repeatedly while Settings opens, stays open and closes. Text remains sharp; the background surface changes live. Check Escape, Cancel and reopening during close, including keyboard focus.
- Resize, maximize, minimize and restore with frozen and animated Dither. It retains the configured background color until a valid frame exists and rebuilds GPU resources after context restoration. Unchanged Dither settings must not redraw a frozen background when another appearance setting changes.
- Native Dither corruption is still an acceptance item. Shaders are unchanged: lifecycle tests do not prove Windows compositor correctness. If corruption recurs, send `app.txt` and a screenshot before/during/after the fade, together with the WebView2 runtime already recorded by native diagnostics. For a specifically requested diagnostic capture, compare one canvas image with the presented window; a correct canvas with a corrupt window points beyond the shader. Do not capture continuously.
