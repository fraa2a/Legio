# TaxLauncher replacement in Legio 0.2.0

The native importer is available before GUI initialization on Windows:

```powershell
& 'C:\Users\USER\AppData\Local\Legio Launcher\legio.exe' --import-taxlauncher 'C:\BACKUP\export.json' --import-report 'C:\BACKUP\import-receipt.json'
```

It resolves the production identifier from the built Tauri configuration and opens `%APPDATA%\dev.fraa2a.legio\legio.sqlite3`. It retains a consistent SQLite backup of an existing database before conversion. The entire import of games, historic sessions, settings, source and a receipt marker runs in one SQLite transaction. Repeat import returns the saved receipt without adding playtime or games again. Changed input with a previously imported migration ID is rejected.

The export includes `schemaVersion: 1`, a UUID `migrationId`, legacy `games`, an allowlisted `preferences` object and a validated `sourceManifest`. Native UUID identities are derived deterministically from legacy IDs so ordinary launch, edit and delete operations work. Windows autostart is applied before a successful receipt; failed registration leaves TaxLauncher installed and can be retried without repeating the database import. Games keep custom names, absolute executable paths and playtime, converting minutes to milliseconds. Explicit Steam app IDs or trusted Steam cover URLs provide identity. Numeric legacy IDs are not Steam app IDs. Existing Legio executable matches and preferences are preserved. The source `https://source.taxphobia.top/store.json` is cached and scheduled for normal refresh. Fresh profiles retain both logging toggles off.

`--validate-source-manifest PATH` validates bridge payloads without opening a window and works on both supported systems. The importer itself is Windows only. The legacy Electron bridge and replacement helper are in the sibling isolated `taxlauncher-legio-migration` workspace; its README contains build, recovery and release ordering instructions. No TaxLauncher feed or production release has been published.

The yellow Steam warning `could not access a configured Steam library: NotFound` comes from an inaccessible configured library folder. Scanning continues on other libraries. This explains why installed games can still appear and launch, but the affected machine's stale path has not been identified because no library configuration was provided. It is separate from migration.
