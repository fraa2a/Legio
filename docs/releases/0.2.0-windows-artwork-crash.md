# Windows artwork stack overflow

## Evidence

The user-provided Windows Error Reporting report and ProcDump capture identify exception `0xc00000fd` in `legio.exe` 0.2.0.0, PE timestamp `0x6acacb3b`, at RVA `0x14779d7`. This is the installer built from PR head `68c7e5bfcb436443a009ba1ed8974a11e2e901d1`.

The faulting instruction is the stack probe's page write. Its caller is requesting a frame of `0x3d8c8` (252,104) bytes. At that point the thread already uses `0xe2ab0` (928,432) bytes of its 1 MiB stack reservation.

The capture contains the executable image and AMD64 unwind metadata. Unwinding from the exception context yields the following application frames before returning through the WebView2 callback:

| Return/fault RVA | Function start RVA | Observation |
| --- | --- | --- |
| `0x14779d7` | `0x14779a0` | Stack probe faults while reserving the next frame. |
| `0x54a3be` | `0x54a3b0` | Probe caller reserves 252,104 bytes before copying and boxing a 252,024-byte future. |
| `0x5eff67` | `0x5efe30` | Runtime dispatch copies that future through a 504,152-byte frame. |
| `0x340eaf` | `0x340e20` | IPC response scheduling uses a 252,088-byte frame. |
| `0x46d26` | `0x45ce0` | Generated command dispatcher calls the scheduling function from the `get_steam_asset` branch. |

The dispatcher branch compares the command bytes against `get_steam_asset` immediately before the observed call. This ties the native stack to the artwork command without relying on unrelated nearest-export names or symbols from a different build. No repeated application frame appears in this trace. The observed failure is excessive nested stack allocation during command scheduling.

Tauri 2.12.1's `InvokeResolver::respond_async_serialized` boxes the task under `debug_assertions`, but passes it by value into its scheduling helper in release builds. This explains why development builds and isolated image codec tests did not exercise the failing release dispatch path.

The image command future has not been polled at the fault. The image decode checkpoints, JavaScript error handlers and Rust panic hook therefore cannot report this exception. In-process logging cannot survive termination of its own host process.

## Regression coverage and acceptance

`get_steam_asset` and `prefetch_steam_hero` pin the asset-loading future in a heap allocation before awaiting it. Their enclosing command futures carry the small pinned pointer instead of embedding the complete asset state machine. This reduces the values copied while Tauri schedules the command on the UI thread.

The artwork and hero-prefetch command futures must remain within a 4 KiB inline budget. The unit test measures the real command future types with the production Wry runtime, without constructing a mock app or issuing network requests. Windows CI runs this check in the release profile in addition to the existing image conversion tests.

The affected Windows machine must still pass populated Library and Store tests, with cold and warm caches and logging both disabled and enabled, before release acceptance. ProcDump is an external diagnostic collector; application logging remains optional and defaults to off.
